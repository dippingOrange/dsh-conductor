## 结论

1. **两个订阅在当前用量下没有省钱**
   - 当前约 **$23.1/月**
   - 全官方约 **$13.0/月**（只比较订阅覆盖的 Worker）
   - 两个订阅反而贵约 **$10.1/月**

2. **只保留一个订阅基本打平**
   - 约 **$13.1/月**
   - 与全官方 $13.0/月 基本持平
   - 前提是能把 Worker 流量集中到一个 provider

3. **$80/月额度严重闲置**
   - 每个订阅给 $80 的 dsv4.1f 用量
   - 订阅覆盖的 Worker 只有约 **$9.9/月** 的 API 等价用量
   - 单个订阅利用率约 **12%**；两个订阅合计约 **6%**
   - 两个订阅的盈亏平衡点：订阅覆盖的 Worker 用量达到 **$20/月**；当前约差一半

4. **Leader 很便宜**
   - 官方 Leader 约 **$3.1/月**
   - 因为 cached input 只按 $0.006/M 计
   - 成本主要被 Worker 订阅固定费占据

## 建议

- 如果 `nqiv` 是免费/内网，并且能承担大部分 Worker，**官方 Leader + nqiv 可能比两个订阅更便宜**；订阅只用于必须走 command-code/opencode 的任务。
- 两个订阅当前每月多花约 **$10**；只留一个订阅与全官方基本打平。
- 如果要保留两个，把订阅覆盖的 Worker 用量提高到约 **$20/月 API 等价**以上，固定费才不亏。
- 如果两个 provider 只是作为备份/质量对比，可以把第二个当作 **$10/月 的保险**，不必强求省回来。
- 继续记录 **Leader / Worker 月度 usage**，否则下个月仍然只能回算。
- 需要按实际账单调整时，只需要替换单价和订阅月费。

## 口径提醒

- `inputTokens` 和 `cacheReadTokens` 是分开的，不能直接相加。
- `cacheRead` 是缓存命中价，通常远低于普通 input。
- 订阅制下 token 量不等于账单；它衡量的是额度和利用率。
- 这是历史日志回算，不包含已删除 transcript，fork/seed 可能有少量重复。
